# Explicit product rule: inspect u'v + uv'

Copy this update into your existing modular_math directory. Supporting
polynomials.py and polynomial_ast.py are unchanged from the earlier stage.
No retraining required; reuse runs/structure and runs/arithmetic-depth8.

## Run

```bash
cd ~/python_workspace/transformer-demo/modular_math
python3 -m unittest discover -s tests -p 'test_product_rule.py' -v
python3 run_product.py --parse-only --expr '(x+1)*(x**2+2)'
python3 run_product.py --structure runs/structure \
  --arithmetic runs/arithmetic-depth8 --expr '(x+1)*(x**2+2)'
```

Expected decomposition:

| Field | Meaning | Reference for this example |
|---|---|---|
| preprocessing.left_expression | u(x) | x+1 |
| preprocessing.right_expression | v(x) | x**2+2 |
| predicted_left_derivative | Neural derivative u' | 1 |
| predicted_right_derivative | Neural derivative v' | 2*x |
| first_product | Predicted u' times original v | x**2+2 |
| second_product | Original u times predicted v' | 2*x**2+2*x |
| output | Sum of the two products | 3*x**2+2*x+2 |

The factored_prediction field retains the construction before collecting terms:
`(1)*(x ** 2 + 2)+(x + 1)*(2*x)` when model predictions are correct.

## What executes each step

AST code recognizes a top-level multiplication and preserves its two children.
Each factor is normalized independently into polynomial terms. The SAME two
neural modules predict monomial derivatives inside both factors. The two factors
are NOT multiplied together before inference, unlike run_ast.py.

Rule selection, polynomial multiplication, integer addition and formatting are
ordinary deterministic code. The network has NOT learned to select the product
rule. There are no extra model weights or extra neural multiplication calls for
final u'v and uv'. Predictions are used as received; reference derivatives never
repair them. A malformed response in either factor fails the complete result.

Both factors are evaluated even if one is zero. Therefore a faulty derivative
may be mathematically masked by a zero multiplier. The report separately checks
factor derivatives and the final expression to expose this distinction.

## Trace fields, in reading order

- preprocessing: original source, left/right factor strings and term lists.
- rule: the hard-coded formula u'v+uv'.
- rule_selected_by / assembly_by: explicitly state which operations are code.
- left_derivative_trace / right_derivative_trace: complete monomial pipeline
  responses. Each term includes post-inference diagnostics, actual received
  operands and generated_ids/generated_tokens as in CHAIN_OUTPUT_WALKTHROUGH.md.
- predicted_left_derivative / predicted_right_derivative: assembled predictions.
- first_product_terms / second_product_terms: lists [coefficient,power] for the
  two predicted branches. The corresponding string fields format the same data.
- factored_prediction: a string assembled from predictions and original factors;
  it is not a token sequence generated by one model.
- output_terms / output: canonical sum of the two predicted branches.
- status: ok means parseable inference, not automatically mathematical correctness.
- diagnostics.correct: equality to a reference produced AFTER inference by the
  independent path expand original product, then differentiate each term.
- diagnostics.left_derivative / right_derivative: separate branch scoring.
- diagnostics.both_factor_derivatives_correct: both derivative polynomials right.
- diagnostics.correct_final_with_wrong_factor_derivative: right final result but
  at least one wrong derivative branch, e.g. masking by a zero factor.

## More examples

```bash
python3 run_product.py --structure runs/structure \
  --arithmetic runs/arithmetic-depth8 --expr '(3*x**3+6*x**2)*(x+2)'
# Reference: 12*x**3+36*x**2+24*x

python3 run_product.py --structure runs/structure \
  --arithmetic runs/arithmetic-depth8 --expr='(-x+2)*(x-3)'
# Reference: -2*x+5
```

For a direct comparison run the same expression through run_ast.py. That path
first expands u*v, so the neural prompts differ; correct mathematics does not
imply identical neural errors across the two paths.

## Scope

Top-level AST operator must be multiplication. Each factor must be a bounded
integer polynomial accepted by polynomial_ast.py: x, integers, +, -, *, powers
0..12. Final factor coefficients |a|<=999; existing model training range is only
|a|<=199 and degrees 0..5. Functions and division are rejected.

For a*b*c, Python's left-associative AST groups it as (a*b)*c. This command applies
one product-rule boundary to those two children; the factor a*b is normalized
algebraically, not recursively differentiated via another product-rule call.
Nested chain rules are likewise not recursively orchestrated in this stage.
Assembly is bounded to degree 24 and coefficient magnitude 10**12.
